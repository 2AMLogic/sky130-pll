- **Methodology / criteria / limitations**:
  - Sampling mechanism: sky130's own `MC_MM_SWITCH` (within-die mismatch, via the corner's `*_mm` `.lib` section) and `MC_PR_SWITCH` (die-to-die process variation, every corner section) parameters, which gate `agauss()`/`gauss()` calls already present in the shipped device models. Each trial's draw is seeded by a distinct ngspice `.options seed=<N>` card -- reproducible per trial, independent across trials. See `sim/harness/montecarlo.py`'s module docstring.
  - Per-trial criterion, part 1 (plumbing): ngspice exits 0, prints the harness's analysis-completion marker (`sim/harness: analysis complete`, echoed by the injected `.control` block), and emits no `Error:` line -- the same check every other unit in this package uses.
  - Per-trial criterion, part 2 (measurement): the loop **locks** within the transient window. Lock criterion: mean output frequency over every sliding window of 20 output cycles stays within +/-5% of 250 MHz through the end of the transient, with at least 20 cycles of in-band data after the lock instant. A trial that never satisfies it is reported as **no lock**, exactly as a PVT point would be, and (per row 9's own wording) contributes no period-jitter figure either -- it is not charged as a jitter failure, because a design that has not converged has no post-lock population to measure jitter over. (Reported, but not gated on, for this manifest.)
  - Period jitter (row 9): the standard deviation of the measured period over a population of at least 20 consecutive post-lock output cycles, divided by that population's mean period, is at most 1% (reported, but not gated on, for this manifest).
  - Measurement method: the same manifest-owned `.control` block a PVT point's `measure` block injects (`sim/harness/measure.py`'s `build_control_block`) is appended after this trial's `MC_MM_SWITCH`/`MC_PR_SWITCH`/seed cards, so each trial runs the manifest's transient window against its own sampled device draw and is reduced by the same threshold-crossing extractor a PVT point's dump is. The waveform dumps themselves are **not** committed -- `sim/README.md`'s retention policy treats them as regenerable from the frozen netlist plus the logged environment.
  - Simulator accuracy: the transient runs under `.options reltol=1e-4` (manifest `measure.options`), injected ahead of the analysis, instead of ngspice's default integrator tolerances; ngspice's internal timestep is capped at 200p (manifest `measure.tran_max_step`, the `tran` card's TMAX) independently of the 20p dump grid, so the grid the edges are interpolated on is finer than the cap the integration runs under rather than equal to it. Stated because at ngspice's defaults (reltol 1e-3, TMAX = the dump step) the timestep controller's own error and the dump grid's resolution show up in a free-running ring's edge times as period jitter of the order of row 9's bound -- see `sim/harness/measure.py`'s 'The integrator's tolerance puts a second floor under this figure' and `sim/integrator-floor/`.
  - Window and initial conditions differ deliberately from sim/pll-lock-mc's, and the reason is cost: that campaign's 50 us window is sized to pay for a cold start from a fully discharged loop filter (24.32-29.72 us of acquisition ramp in its own record 20260925-224917-3a2dd6e) before any post-lock population exists, at roughly an hour and a half of simulator time per trial. This unit pre-charges the loop filter's three storage nodes to 0.865 V -- the fixed control voltage sim/vco-clk-transition/records/20260925-110645-810cd82.md states 'puts the ring near the row-9 operating point' -- so the ramp is skipped and a 20 us window buys a long post-lock population. The consequence is stated rather than hidden: a pre-charged start is NOT the DR-005 cold start row 9's evidence is taken under, so an arm's absolute figure here is not interchangeable with a sim/pll-lock-mc draw's, and this unit's own nominal arm exists precisely so the family is read as a RATIO measured under one set of conditions rather than as absolute numbers borrowed across two. `gate_on_bound` is false because every degraded arm is expected to exceed row 9's bound by construction -- that is the finding, not a failure (same setting and same reasoning as sim/integrator-floor). `require_lock` is false for the same reason it is false in sim/pll-lock-mc: a run that completes but never locks is evidence about this arm at this window, recorded as such.
  - Analysis: pre-charged transient, closed loop, one sky130 statistical draw (`tran 20p 20u 0 200p` under `.options reltol=1e-4`, injected by sim/harness/measure.py from this manifest's own measure block).
