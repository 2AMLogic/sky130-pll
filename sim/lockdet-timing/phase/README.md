# LOCK phase-window delay chains (issue #275)

Physical PVT characterization of the acquisition (`W_acq`) and release
(`W_rel`) phase-window delay primitives for the provisional LOCK detector,
part of #259 within #231. This is primitive evidence, **not** the LOCK
circuit: no sample flops, counters or loop integration. DR-007 stays
`proposed` and spec row 16 stays DRAFT; the bands below are the reducer's
constants (`sim/harness/locktiming.py`) and are not changed here.

Bands (DR-007 Table 2): `W_acq` 1.5-4.0 ns, `W_rel` 4.5-10.0 ns,
max(`W_acq`) < min(`W_rel`) (strict), max(`W_rel`) < 12 ns (strict).

## Candidates

Generated by `design/lock-detector/timing/gen_phase_windows.py` (pure text;
it inlines the cell subcircuits verbatim from the pinned PDK's
`sky130_fd_sc_hd.spice` so a batch worker needs no local library path).
Re-running it reproduces every file below byte-for-byte; `manifest.json`
carries each file's SHA-256.

| candidate | acquisition chain | release chain | cells | cell area (liberty) |
| --- | --- | --- | --- | --- |
| `s50` | 7 x `sky130_fd_sc_hd__clkdlybuf4s50_1` | 18 x `sky130_fd_sc_hd__clkdlybuf4s50_1` | 25 | 25 x 10.0096 = 250.2 um^2 |
| `s25` | 14 x `sky130_fd_sc_hd__clkdlybuf4s25_1` | 39 x `sky130_fd_sc_hd__clkdlybuf4s25_1` | 53 | 53 x 10.0096 = 530.5 um^2 |

All cells are drive strength `_1`, non-inverting, chained output-to-input
from one input net `IN`; each chain's last stage drives its tap (`ACQ`,
`REL`) into a declared 10 fF load. Both chains of a candidate share `IN`,
`VDD` and `GND`. Cell area is the liberty `area` attribute
(`sky130_fd_sc_hd__tt_025C_1v80.lib`), placement-free: no routing, no
sample flops, no fill. Taps per candidate: one acquisition tap, one release
tap (stage counts above).

Each netlist is run under two manifests that differ only in edge polarity:
`<id>-rising` measures the input rising crossing to the next tap rising
crossing, `<id>-falling` the falling pair. The netlist is identical, so the
two polarities come from separate batch jobs on the same deck.

Files:

* `design/lock-detector/timing/phase_windows.sch` - both candidates' chains
  (xschem, generated).
* `design/lock-detector/timing/netlist/phase_windows.spice` - the DUT
  subcircuits `phase_win_s50`, `phase_win_s25`.
* `tb_phase_windows.sch` - stimulus and loads (generated).
* `candidates/<id>.spice` - runner decks (cells + DUT + stimulus, `@VDD@`
  placeholder); `candidates/control.spice` the negative control;
  `candidates/<id>-<edge>.json` the reducer manifests.

## Stimulus, startup and measurement conventions

* Supply `VDD` = grid supply (1.62 / 1.8 / 1.98 V); `GND` = 0; cell bulk
  pins `VPB`/`VNB` tied to `VDD`/`GND`.
* `IN`: `PULSE(0 VDD 150n 100p 100p 100n 250n)` - 100 ps (0-100 %) slew,
  rising at 150/400/650 ns, falling at 250/500/750 ns. The input is an ideal
  source (no driver-strength model).
* Reset/startup: the chains have no reset pin. `RSTB` is a separate ideal
  source stepping to `VDD` at 20 ns; it marks the declared enable instant only
  (`startup` trace). From 0 to 150 ns `IN` is held low, so every chain node
  reaches its DC state before the first edge; the analysis window opens at
  100 ns (enable 20 ns + settle 60 ns = 80 ns <= 100 ns).
* Window 100-800 ns, transient step 20 ps. Crossing threshold 0.9 V fixed for
  all supplies (50 % at 1.8 V; 55.6 % of 1.62 V, 45.5 % of 1.98 V). This is a
  declared absolute threshold, not a supply-ratio one.
* The reducer takes the first in-window input crossing of the declared
  polarity and the next tap crossing of the same polarity.
* `tick`/`raw` are the input stimulus itself (250 ns period); their graded
  `tick` band only confirms the stimulus period and is **not** watchdog
  evidence (#276 owns that).

### Mapping to phase-window half-widths (assumption, awaiting #260)

DR-007's handoff realizes the phase test by delaying `REF` and `FBCLK` by
`W` through `sky130_fd_sc_hd` delay chains and sampling with flops. This
campaign equates the half-width with the chain's propagation delay:
`W_acq = t_pd(acq chain)`, `W_rel = t_pd(rel chain)`, input crossing to tap
crossing at the declared threshold. It assumes the sample flops' setup/hold
and clock-to-Q offsets cancel between the two compared arms and that the
in-circuit load and input slew match the declared 10 fF / 100 ps. None of
that is validated here; #260 must validate it in the assembled circuit.
The DR-007 phase test compares rising edges of `REF`/`FBCLK`, so the
`-rising` manifests are the selection basis; the `-falling` manifests are
recorded because a realization that windows on falling edges (or clocks a
sample flop from an inverted tap) sees that polarity instead.

## Switching current and shared VDD

Measured (local, single corner tt/27 C/1.8 V only, ideal input source, the
two 10 fF tap loads included; integral of the supply current):

| candidate | charge per input rising edge | per falling edge | per input period | peak supply current |
| --- | --- | --- | --- | --- |
| `s50` | 0.41 pC | 0.38 pC | 0.80 pC | 0.23 mA |
| `s25` | 0.62 pC | 0.59 pC | 1.22 pC | 0.36 mA |

Estimates (not measured): average current is charge per period times the
edge rate, e.g. `s50` at a 10-25 MHz reference is about 8-20 uA per delayed
signal; DR-007 delays both `REF` and `FBCLK`, so double it. The peak current
is a sub-ns burst per stage as the edge travels the chain (about 2.7 ns for
the acquisition tap, about 6.9 ns for the release tap at nominal). If the
chains share `VDD` with the VCO or charge pump, that burst lands right after
each reference edge, i.e. inside the phase-comparison interval; whether it
disturbs the loop is not evaluated here and is a #260/#231 integration
question. PVT variation of the current was not measured.

## Reproduction

```
python3 design/lock-detector/timing/gen_phase_windows.py   # regenerate; no diff expected
# plan only
python3 sim/run_locktiming.py --candidate sim/lockdet-timing/phase/candidates/s50-rising.json=sim/lockdet-timing/phase/candidates/s50.spice --points all --dry-run
# physical grid, one candidate (klt batch backend; no local fallback)
python3 sim/run_locktiming.py --candidate sim/lockdet-timing/phase/candidates/s50-rising.json=sim/lockdet-timing/phase/candidates/s50.spice \
    --points all --records-dir sim/lockdet-timing/phase/records
```

A rerun of an already recorded matrix needs `--supersedes <record-id>`.
