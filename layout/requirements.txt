# Pinned klayout-tools (`klt`) install for layout/'s DRC/LVS flow (issue #2).
#
# 2AMLogic/sky130-bandgap's own layout/requirements.txt (source commit
# f3b2b2e461938e323670498bcdbe9f4ec7de699b) pins an exact git commit rather
# than a PyPI version, because at the time it was written PyPI's
# `klayout-tools` release (v0.1.0) shipped only five verbs
# (`layers`/`stats`/`cells`/`drc`/`pdk`) -- this flow needs `gen`, `extract`
# and `lvs` too, which were `main`-only.
#
# That gap closed for a while: PyPI's `klayout-tools==0.2.0`
# (https://pypi.org/project/klayout-tools/0.2.0/) ships `gen`/`extract`/`lvs`,
# so this file pinned that plain PyPI version from issue #2 through issue #16.
#
# Bumped to a git-commit pin for issue #46 (2026-08-19). The full argument --
# what the version pin bought, what it cost, and what was measured either way
# -- is layout/klt-pin-decision.md; read that first. In short: `0.2.0` (built
# 2026-08-04) is hundreds of commits behind the tool's `main`, PyPI has had no
# release since, and five of the eight `klt` gaps the PLL layout (#16) had to
# work around are already fixed on `main`. Each of the five was verified to
# behave as claimed at the commit pinned below, rather than trusted from its
# issue's closed status:
#
#   * 2AMLogic/klayout-tools#1057 -> merged via #1070. `gen-compose`'s router
#     now checks a candidate route against every already-drawn route in the
#     same request and rejects the collision (`legs[].reason` "crosses
#     already-routed net '<net>'") instead of drawing both. Measured on this
#     design: at `0.2.0` all 7 routes the router spot-check drew came back
#     merged by `klt extract` onto 2 electrical nodes; at this pin the same
#     spot-check draws 51 legs and the extractor reports exactly one merged
#     node (a different, still-open defect -- see klt-pin-decision.md).
#   * 2AMLogic/klayout-tools#1073 -> merged via #1094. A `connectivity[]` net
#     with more than two pins routes as a spanning tree of two-pin legs, so a
#     shared rail or a fanout net is expressible at all. 53 of this design's
#     60 declared nets are such bundles; at `0.2.0` every one was unroutable
#     by construction.
#   * 2AMLogic/klayout-tools#1059 -> merged via #1074. A `klt draw` response
#     carries `generator: "draw"`, so drawn geometry composes as a
#     `gen-compose` block without a hand-forged block report.
#   * 2AMLogic/klayout-tools#1117 -> merged via #1137. `klt gen cap_array`
#     draws a matched MiM-capacitor row (sky130 capm/met3) with a top-plate
#     via and landing pad. Available at this pin, not yet adopted by this
#     flow, which still draws bare plates with `klt draw`: adopting it is
#     layout work with its own evidence, not a pin bump.
#   * 2AMLogic/klayout-tools#1166 -> merged via #1174. A `gen-compose` block
#     takes an `orientation` ("mirror_x"/"mirror_y"/"rotate_180"), which is
#     what a multi-row standard-cell block needs to abut rows power-rail to
#     power-rail. Also available, also not yet adopted (the divider is one
#     row, so nothing in the shipped layout needs it today).
#
# Two behaviour changes this pin carries are load-bearing for the checked-in
# evidence, and are called out here so a reader does not mistake either for a
# regression:
#
#   * `klt extract` now includes a perimeter/fringe term in a MiM capacitor's
#     value (`CapacitorDevice.perim_cap_f_um`, 1.9e-16 F/um in sky130's
#     curated deck), correcting a documented one-sided undercount. The PLL
#     record's schematic-vs-extracted capacitor cross-check now predicts the
#     same two-term value (layout/bin/pll_layout.py's MIM_PERIM_CAP_F_UM), so
#     the comparison stays exact instead of being loosened to absorb it.
#   * sky130's curated deck declares a `dummy` marker layer and `mos_array`
#     draws it, so `klt extract` suppresses the trivial cell's 4 dummy-column
#     units: `device_count` 8 -> 4, `dummy_devices_dropped` 0 -> 4.
#     layout/trivial-cell/reference*.spice are re-stated at 4 M-cards --
#     see reference.spice's own header for why that is the topologically
#     correct reference and not a relaxation to make a comparison pass.
#
# Why a git commit and not a newer release: there is no newer release. PyPI's
# latest is still `0.2.0`, and every fix above sits in the tool's own
# CHANGELOG under "Unreleased" (2AMLogic/klayout-tools#953 is the
# release-cadence gap this repo cross-confirmed). A commit pin is reproducible
# in the way that matters here -- a git object hash names one immutable tree,
# re-fetched identically -- it simply does not get PyPI's artifact
# immutability or a hash-checkable wheel. sky130-bandgap's own
# layout/requirements.txt has pinned by commit through eight deliberate bumps
# for the same reason, and this repo's CLAUDE.md says to mirror that plumbing
# rather than reinvent it.
#
# Bump discipline, mirrored from sky130-bandgap: pin an exact commit, never
# floating `main`; state in this header what the bump picks up and what it
# changes; and re-run BOTH layout/bin/run-trivial-cell-flow.sh and
# layout/bin/run-pll-layout-flow.sh, checking the refreshed records in, as the
# non-regression proof. Note that `klt --version` still reports `0.2.0` at
# this commit (upstream has not bumped the package version), so
# layout/bin/setup-venv.sh reinstalls with `--force-reinstall`: pip would
# otherwise consider an already-installed `0.2.0` up to date and silently keep
# the old build.
