# LOCK-detector timing handoff (issue #276, part of #259 within #231)

Combined circuit-timing evidence for the provisional LOCK detector. DR-007
stays **proposed**, spec row 16 stays **DRAFT**, and the behavioral reference
(`lockdet_ref.py`) is unchanged. Q/R/K logic, CDC, reset-to-LOCK latency and
clock-loss transitions belong to #260/#261; nothing here establishes them.

## Verdict

**The handoff is NOT ready, and #260 remains blocked.** Two independent
reasons, neither a spec relaxation:

1. Phase windows (#275, complete 45/45 physical records): no candidate meets the
   DR-007 Table 2 `W_acq` / `W_rel` bands (see `sim/lockdet-timing/phase/README.md`).
2. Watchdog (this issue): **no complete 45-point watchdog grid exists.** Only
   one nominal point (tt, 27 C, 1.8 V) of the selected candidate `wdb` was
   measured, plus negative controls. Every attempt at the full grid ended with
   points missing or failed for tool/fleet reasons (below). This is missing
   evidence (`INCONCLUSIVE`), not a measured band miss, and it is not full-grid
   completion. **Issue #276 stays open**: a concrete runner/fleet capability gap
   remains. A superseding decision record is only relevant if a *complete* grid
   later shows a miss.

Mechanical grade (reducer `handoff`, `design/lock-detector/timing/grade_combined.py`;
nearest rising phase candidate `s25-rising`, record `lt-20261012-220148-142698`,
with the `wdb` nominal record `lt-20261013-102052-850129`): scope FULL,
`handoff_ready: false`; `phase-acq` MISS (`w_acq`), `phase-rel` MISS (`w_rel`;
hysteresis and 12 ns ceiling PASS), `watchdog` INCONCLUSIVE (`tick`, incomplete).

## Watchdog primitive (selected candidate `wdb`) - MEASURED nominal only

Independent of REF, FBCLK and CLK: its only inputs are `EN`, `RSTB` and the
supply. Sources: `design/lock-detector/timing/watchdog.sch` (schematic),
`netlist/watchdog.spice` and `sim/lockdet-timing/watchdog/candidates/wdb.*`
(generated by `gen_watchdog.py`), `sim/lockdet-timing/watchdog/tb_watchdog.sch`
(stimulus).

| item | value |
|---|---|
| enable gate | 1 x `sky130_fd_sc_hd__nand2_1` (EN, feedback) |
| ring delay | 29 x `sky130_fd_sc_hd__buf_1`, drive 1, in series (the NAND is the only inverting stage) |
| divider | 6 x `sky130_fd_sc_hd__dfrbp_1` ripple toggle (D = Q_N, CLK = previous Q), ratio /64, `RESET_B` = `RSTB` |
| taps | `RAW` = last ring buffer output (also feeds the NAND); `TICK` = Q of flop 6 |
| loading | 10 fF on `RAW` and on `TICK`, plus the first flop clock pin on `RAW` |
| thresholds | 0.9 V absolute, all supplies |
| stimulus | `EN` and `RSTB` step 0 -> VDD at 20 ns (100 ps edge); VDD fixed per group |
| settling / window | enable 20 ns + settle 60 ns; window 100 ns - 2 us; output step 25 ps; `.options trtol=1`; timeout 3600 s |
| startup aid | none: no `.ic`, no ideal forcing. With `EN` low the NAND holds the ring at a DC state; raising `EN` starts it from that state. `RSTB` low holds the divider cleared. |
| area (liberty, placement-free; estimate) | 3.7536 (nand2_1) + 29 x 3.7536 (buf_1) + 6 x 28.7776 (dfrbp_1) = 285.3 um^2 |

Measured at tt / 27 C / 1.8 V (batch record `lt-20261013-102052-850129`, job
`klt-sim-f42e320577d2`, one point, evidence class `physical`):

| quantity | value | note |
|---|---|---|
| raw-ring period | 3.470 ns | diagnostic, not banded |
| divided tick | 222.1 ns | in the 125-500 ns band (one point only) |
| startup latency | 3.492 ns | EN release to first RAW rising crossing |

The divided tick equals 64 x raw period, as expected for a /64 ripple chain. The
band applies to the tick only. No temperature, supply or process spread of
`wdb` has been measured, so nothing here shows the band holds across PVT (a
ring built from `buf_1` will move strongly with supply and temperature; this is
an expectation, not a result).

## Why there is no complete grid (all attempts recorded)

1. **Full grid, one fleet job per supply (15 corners each)** - record
   `lt-20261013-142513-681682`, evidence class `incomplete-not-physical`, all 45
   points `SIM_FAILED`: `batch_job_timeout` for the 1.62 V and 1.8 V jobs (the
   fleet kills any job at its 3600 s whole-job ceiling) and `batch_poll_timeout`
   for 1.98 V. These are explicit failed points, not silent gaps.
2. **Artifact size** (found earlier): `klt sim` default `save all` ASCII raw
   plus JSON copy is ~3.5 GB per corner for this ring; fixed in this pass by
   requesting `options.save_mode = "netlist"` (only `RAW`/`TICK`), which gives
   ~7 MB per corner. Related generic tool issue: `2AMLogic/klayout-tools#3211`.
3. **Full grid, one fleet job per supply x temperature (5 corners each,
   `--split-temps`, 18 jobs)**: individual jobs finished in ~10-12 min, but job
   durations are not stable (one 1.62 V / 27 C job hit the 3600 s ceiling
   while an earlier identical job finished in ~11 min), and 18 serial jobs need
   about 3 h. The only way to run that here is a single foreground-attached
   runner process, which the host's 2 h background-task limit killed before it
   wrote its record; the host rules forbid detaching it. Observations from the
   killed runs (1.62 V / -40 C and +125 C slices returned waveforms; one
   +27 C slice timed out) are **not** committed evidence, because no record was
   written. The runner writes one record only at the very end and has no
   resume or per-supply/temperature selection, so partial progress is lost.
4. Control `wdb-ctl-en` (EN held low) and the `wdb` nominal point are committed;
   the control classifies as `ABSENT_CROSSING`.

5. **Resumable runner (this increment) and bounded resumed runs.** The runner now
   writes one append-only group record per finished fleet job under
   `sim/lockdet-timing/watchdog/records/groups/<matrix-id>/<group>.<stamp>.json`
   (plus the request, body, report and stderr beside it), skips groups that
   already have a good record (`--resume`), can bound an invocation
   (`--max-groups N`, `--only REGEX`) and writes the combined record only when
   every group has a good record (`--finalize-incomplete` overrides). A rerun of
   a failed group is a new file naming the one it supersedes; nothing is edited
   or deleted. Measured outcome of the resumed attempts (the plan is 9 jobs of
   5 corners, `--split-temps`, one candidate):

   | group (supply, temperature) | outcome |
   |---|---|
   | 1.62 V, -40 C | 5/5 corners returned waveforms, reduced rows `OK` (group record `...1.62v_-40c.20261013-204006-424780`) |
   | 1.62 V, +27 C | all 5 corners `nonconvergence` ("Dynamic gmin stepping failed"), `SIM_FAILED` |
   | 1.62 V, +125 C | no record: job still polling after > 1 h 50 min when the 2 h background limit killed the runner |
   | 1.80 V, -40 C | `batch_job_timeout` (job exceeded the 3600 s fleet ceiling), `SIM_FAILED` |
   | 1.80 V, +27 C | all 5 corners `nonconvergence`, `SIM_FAILED` |
   | 1.80 V, +125 C | no record: submit waited on fleet capacity, runner killed at the background limit |
   | 1.98 V, all three temperatures | not attempted |

   So 1 of 9 groups (5 of 45 points) has good measured rows; no combined record
   exists, the grid is **not complete and not graded**, and no PVT conclusion is
   drawn. The `wdb` +27 C groups fail to converge at 1.62 V and 1.8 V even
   though the earlier single-corner nominal record (tt, 27 C, 1.8 V) converged;
   whether that is the group request (five corners, `save_mode=netlist`), the
   fleet image or non-determinism is **not established** here. Fleet job
   durations remain unstable (10 min to > 1 h for equivalent jobs). No local
   fallback was used.

Net: the runner capability gap (record per finished job, rerun only missing
groups) is closed. What remains is fleet reliability (job ceiling, capacity
waits) plus the unexplained +27 C nonconvergence, both outside this issue's
"no new execution framework" scope. Reproduction of the attempt is below.

## Negative controls (actual classification, before any grid)

* `wdb-ctl-en` (`wdb`, EN held low): `ABSENT_CROSSING`, no values (`lt-20261013-102301-784991`). Earlier control with the same expected result: `lt-20261013-085627-989271`.
* `wd-ctl-en` (`wd`, EN held low): `ABSENT_CROSSING` (`lt-20261013-061534-163034`).
* `wd-ctl` (AND2 enable gate: non-inverting loop): `SIM_FAILED`, klt exit 4 with `nonconvergence` on the bistable DC point (`lt-20261013-061245-358912`, `incomplete-not-physical`). It is a failure, not an oscillation classification; kept as evidence.

Local single-corner cross-checks of the earlier `wd` deck (one `ngspice -b`
each, tt / 27 C / 1.8 V; `RAW` and `TICK` inspected separately): disable/re-enable
(EN low holds `RAW` high, re-enable restarts immediately at the same period) and
reset (`RSTB` low clears `TICK`; the ring keeps running; `TICK` rises again
~3 ns after release) behaved as designed. These are local, not batch, and are
not repeated for `wdb`.

## Switching current and shared supply

Not measured. Estimate (not measured): a free-running ring plus six toggling
flops draws continuous supply current while enabled and injects supply noise at
the ring frequency and its harmonics; whether that disturbs a shared VCO or
charge-pump supply is a #260/#231 integration question. Gate `EN` when the
watchdog is not needed and give it its own supply branch if the loop shares VDD.

## Backend / client / runner

Backend `klt sim --backend batch` accepted the smoke and every group. Runner klt
0.7.0 vs client 0.7.1.dev (`version_skew: true`), exit 4 accepted as
waveform-only by `locktiming_cli.waveform_only_exit`. Capability gaps found:
artifact size/memory (klayout-tools#3211), whole-job ceiling vs 15-corner
bound, and (now closed) the missing resume / partial-record path in the runner.
